# CLAUDE.md — conventions for working on CreaseIQ

Read `PLAN.md` (binding spec) and `PROGRESS.md` (current state) before doing anything.

## Environment
- Windows 11 dev machine, PowerShell. Python 3.12 venv at `.venv` (`.venv\Scripts\python`).
- Package lives in `src/creaseiq` (src layout), installed editable: `pip install -e .[dev]`.
- Git identity is repo-local (never touch global config). Never force-push. Never commit secrets.

## Commands
- Tests: `.venv\Scripts\python -m pytest`
- Lint/format: `.venv\Scripts\ruff check .` / `.venv\Scripts\ruff format .`
- Types: `.venv\Scripts\mypy src`
- Pipeline: `.venv\Scripts\creaseiq all`
- App: `.venv\Scripts\streamlit run src/creaseiq/app/Home.py`

## Code conventions
- Layering (downward only): app/cli → services → analytics|features|models|simulation|reporting → data|db → config|logging_setup|exceptions|utils. Enforced by `tests/unit/test_architecture.py`.
- Public functions: type hints + Google-style docstrings citing FR IDs (e.g. `FR-02`).
- Analytics = pure functions returning DataFrames. No raw f-string SQL anywhere.
- Raise typed errors from `creaseiq.exceptions`; never bare `Exception`.
- Deterministic: seeds from `configs/config.yaml`; no randomness without a seed.
- Never use raw `team1`/`team2` order as a model feature (semantic drift pre/post 2018).
- Every number in docs/report comes from `reports/*.json` generated by code.

## Git workflow
- Branch per unit of work: `feat/…`, `fix/…`, `docs/…`, `test/…`, `chore/…`.
- Conventional Commits, small and atomic, body explains *why*.
- Merge to `main` with `--no-ff`; tag each phase `v0.N.0`.
- Update `PROGRESS.md` and `CHANGELOG.md` at the end of each phase.
