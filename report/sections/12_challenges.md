# 12. Challenges Faced

Engineering CreaseIQ presented several practical hurdles that were identified, diagnosed, and resolved throughout development (documented contemporaneously in `PROGRESS.md` and our ADRs):

1. **Undocumented temporal semantic drift:** The most insidious data trap was discovering that from 2018 onward, the raw `team1` column consistently designates the team batting first, whereas prior to 2018, team ordering was arbitrary. Because the column title gives no hint of this rule change, any machine learning pipeline that blindly consumes `team1` as the primary team learns batting order through a covert side channel. We uncovered this by plotting season-by-season bat-first frequencies. Our solution derives actual batting order from toss records and orients matches using hash-based coin flips (ADR-005).
2. **Super-over score contamination:** Early exploratory profiling revealed impossible anomalies, such as scorecards recording a team "losing 12 wickets". Cross-referencing against historical match reports revealed that every single tied match in the raw corpus had aggregated super-over runs and wickets onto the regulation 20-over totals (and in one game, two super overs). We corrected this by manually auditing each tie against two independent match reports to restore regulation scores (ADR-004).
3. **Misclassified abandoned fixtures:** A contest between Punjab Kings and Delhi Capitals on 08-05-2025 was suspended at 10.1 overs due to an unexpected stadium security blackout, voided entirely by match officials, and replayed from scratch at a neutral venue two weeks later. In raw records, it appeared identical to a routine weather washout, which would have contaminated historical run distributions had we not investigated the specific match date.
4. **Weak recall in Duckworth-Lewis heuristics:** Standard margin inspection heuristics caught only rain-affected games where the margin contradicted normal batting sequence rules. Rain-shortened chases won "by N wickets" are completely indistinguishable from standard full-length chases in aggregate match summaries. We resolved this by fusing our margin heuristic with an externally verified catalog of all historical rain-shortened IPL matches.
5. **Stadium identity fragmentation:** Ground canonicalization presented three distinct challenges: a demolished stadium rebuilt on the same site under a new name (Motera to Narendra Modi Stadium), two distinct stadiums located in the same metropolitan territory (Mullanpur versus Mohali), and commercial sponsorship naming rights changes (MCA Pune). Resolving these ground identities collapsed 60 raw string spellings into 37 authentic physical venues.
6. **Toolchain and runtime modernization:** Our initial project outline assumed Python 3.11, but updated releases of NumPy (2.5) and SciPy (1.18) strictly mandate Python 3.12 or newer. Moving to modern runtimes resolved dependency conflicts and unlocked modern typing syntax across the codebase (ADR-002).
7. **Accidental secret exposure during planning:** During initial architecture drafting, a personal repository access token was pasted into a markdown scratchpad. Recognizing the security risk before the initial Git commit, we purged the token, migrated local authentication to the GitHub CLI (`gh auth login`), and built a pre-commit secrets-scanning test into the test suite.
8. **Pandas iteration bottlenecks:** During initial feature engineering runs under pandas 3, iterating over 950 date partitions using `itertuples` caused feature builds to take over 7 seconds. Profiling highlighted over 117,000 internal indexing operations. Refactoring the state machine to ingest plain dictionary records dropped feature generation time to 0.33 seconds—a 21× speedup that made automated walk-forward cross-validation feasible.
9. **Candidly reporting negative holdout results:** On the 2025–26 holdout dataset, no trained model beat an uninformative 50/50 coin flip. In academic contexts, the temptation is strong to quietly tune hyperparameters until the holdout turns positive. Instead, we preserved the locked model selection hash, reporting the plateau as an authentic scientific finding on post-2023 strategic shifts.
10. **Catching design oversights during peer review:** An internal review of our initial plan revealed that our planned chase-rate baseline had computed league averages across all seasons simultaneously—a clear violation that would have leaked holdout base rates into historical folds. Similarly, the toss hypothesis test had inadvertently conditioned on tactical decisions. Both flaws were caught and rectified prior to model training (`docs/plan_review.md`).
11. **Subtle runtime and typing bugs:** Our automated test harness exposed several corner cases: Streamlit's internal logger initialization silently suppressed our custom module loggers; an export function assumed output directories existed on disk; Mypy caught a variable shadowing bug in the model registry; and franchise validity rules would have rejected new match uploads for subsequent seasons without dynamic year clamping.
12. **Line-ending corruptions on Windows checkouts:** During our fresh-clone reproduction drill on Windows 11, the pipeline failed its raw-data SHA-256 check because Git's default `core.autocrlf` setting had converted LF line endings to CRLF on checkout. We introduced a comprehensive `.gitattributes` configuration marking scorecard datasets and binary models as byte-exact, ensuring cryptographic consistency across platforms.
13. **Handling blocked and noisy online sources:** Several sports data portals aggressively block automated web scrapers, and automated summarizers frequently conflated statistics from different tournaments. We relied exclusively on raw Wikipedia wikitext, official BCCI tournament regulations, and cross-checked match scorecards, assigning confidence scores to every verified fact.
