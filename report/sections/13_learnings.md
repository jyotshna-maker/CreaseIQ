# 13. Learnings & Key Takeaways

1. **Domain investigation outweighs model complexity:** The most impactful engineering breakthroughs in CreaseIQ came from profiling data rather than tweaking loss functions. Discovering the 2018 batting-order shift, finding super-over scores hidden inside regulation innings totals, and disambiguating abandoned games had far more impact on predictive validity than testing extra neural architectures.
2. **Leakage is subtle, pervasive, and often structural:** Data leakage rarely occurs as obvious label copying. More often, it enters through global preprocessing aggregations, non-temporal validation splits, post-innings scorecard indicators, or even row presentation ordering. The only reliable defense is enforcing structural chronological barriers and verifying them with adversarial unit tests.
3. **Intellectual honesty over inflated metrics:** Rigorous walk-forward validation and untouched holdout splits demonstrated that pre-match T20 prediction hovers near a coin flip. The broader academic literature confirms that twenty-over cricket is dominated by high inherent randomness [2], [3]. Projects claiming 85–90% pre-match accuracy almost invariably suffer from unaddressed data leakage.
4. **Calibrated probabilities matter more than binary accuracy:** In high-uncertainty domains, classification accuracy is an uninformative metric because it ignores prediction confidence. Optimizing for calibrated cross-entropy ensures that when the system estimates a 60% win probability, the team actually prevails three out of five times in the long run [9].
5. **Statistical tests require effect sizes and power:** Merely reporting a non-significant $p$-value provides little insight without knowing the minimum detectable effect. Our toss hypothesis test does not claim that the toss has zero effect; rather, it demonstrates that any true underlying effect is bounded within approximately four percentage points.
6. **Mathematical symmetry should be architectural:** Enforcing anti-symmetric feature formulations and eliminating intercept terms in linear classifiers guaranteed exact directional invariance by construction, eliminating directional bias.
7. **Occam's razor holds on modest sample sizes:** Constrained by roughly 1,000 historical matches, the one-standard-error rule consistently selected regularized linear models over gradient-boosted trees. When sample size is bounded, non-linear ensemble variance quickly overwhelms signal.
8. **Engineering rigor makes experiments trustworthy:** Deterministic random seeds, pinned dependencies, declarative configurations, cryptographic artifact manifests, and automated CI pipelines transformed "works on my machine" into reproducible experimental evidence.
9. **Architectural layering accelerates development:** Decoupling business logic from user interfaces meant every analytical use case, prediction flow, and data pipeline was thoroughly testable headlessly via automated CLI runners, without needing a web browser.
10. **Living documentation protects project integrity:** Maintaining Architecture Decision Records (ADRs) at the moment choices were made provided invaluable context during code reviews, eliminating guesswork and providing clear justifications during academic viva evaluations.
